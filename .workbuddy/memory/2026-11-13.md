## VS BuildTools 安装连败两次后的真凶：BackgroundDownload.exe 锁住 Installer 目录

第一次安装 `exit code 5002`（4m05s），第二次同样 5002（3m49s）。日志：

```
Error 0x80131500: Failed to extract: 文件夹 C:\Program Files (x86)\Microsoft Visual Studio\Installer
或其 中的文件已被另一个程序锁定
  at Bootstrapper.CopyContents(...)
```

**失败点在 bootstrapper 自更新**：本地 installer 是 3.14，需升到 4.12，升级动作是把整个 `Installer` 目录改名挪走再写新的。

排查路径（全部排除后才找到真凶）：

| 假设 | 验证 | 结论 |
|---|---|---|
| UAC 没弹窗 = 没提权 | `EnableLUA=0`，UAC 被系统完全禁用；写 `C:\Program Files (x86)\_test.tmp` 成功 | 排除，本来就是管理员 |
| 目录 ACL 拒绝 | 逐条打印，**全是 Allow 无 Deny**，Administrators FullControl，Owner=BUILTIN\Administrators | 排除 |
| 父目录缺 DELETE_CHILD | 父目录 ACL 同样正常；在父目录下新建子目录并 rename 成功 | 排除 |
| 沙箱拦 Program Files 的 rename | 在 `Program Files (x86)` 下新建目录并 rename → OK | 排除 |
| 是重解析点/junction | `LinkType` 为空，`Attributes: Directory` | 排除 |
| explorer 占用 | 重启 explorer 后仍被拒 | 排除 |
| 目录内某个文件被独占 | **目录内 6 个子项逐个 rename 全部成功** | 关键线索：目录本身被锁，不是文件 |

突破口：下载 Sysinternals `handle64.exe`（`live.sysinternals.com/handle64.exe`，416 KB）跑
`handle64.exe -nobanner -accepteula -a "Microsoft Visual Studio\Installer"`：

```
BackgroundDownload.exe pid: 15392  type: File  ...\Installer\resources\app\ServiceHub\Services\Microsoft.VisualStudio.Setup.Service\*.dll  (十几个)
```

**真凶：`BackgroundDownload.exe`（PID 15392，启动于 15:35:56，比我的第一次安装还早 20 秒）**。
它加载了 `Installer\resources\...` 下十几个 DLL，只要它活着，目录就无法改名。而每次重试安装又会 fork 新的，于是永远失败。

**解法**：`Stop-Process -Name BackgroundDownload -Force` → 立刻 rename 测试通过 → 第三次安装越过 4 分钟死亡点，`setup.exe` 主进程出现，Packages 缓存从 1916.8 → 1982.2 MB 持续增长。

**沉淀成经验**：
1. VS installer 报"目录被锁定"时，**别只看 `vs_*` 进程**，`BackgroundDownload.exe` 也会锁 Installer 目录。
2. 判断"目录被锁 vs 权限不足"的手法：**目录内子项能 rename 但目录本身不能 → 一定是句柄占用**；两者都不能 → 权限问题。
3. `handle64.exe` 是这类问题的终极定位工具，比猜进程名快得多。
4. `EnableLUA=0` 的机器上 `Start-Process -Verb RunAs` 不会弹窗（因为没有 UAC），容易误判"提权没发生"。

### 关键判断（值得记的只有这些）

1. **不新开窗口**。项目既定决策（记忆里早就写了"不新开 overlay 窗口，省 290 MB"），这次严格照做：把面板窗口摘边框、置顶、缩成卡片。零内存增量。
2. **量高度不能量卡片**。卡片 `overflow:hidden` + 撑满窗口 → `scrollHeight` 恒等于窗口高度，会死循环。必须量内部滚动容器 `.ov-text` 的 `scrollHeight` 再加头部与内边距。
3. **先出卡片再翻译**。在线引擎 600–1200 ms，先摆位置显示"翻译中…"，感知上比原地干等快得多。
4. **发送失败也要进卡片**。翻译挂了就在卡片里显示原因，比"卡片不出现"更容易理解。
