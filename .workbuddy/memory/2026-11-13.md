## 路径无关性查证（用户提出"最终版不硬性固定路径"）

逐层查了运行时路径解析，**结论是这条约束本来就不存在，是误解**：

- 源码零硬编码绝对路径。模型走 `SHOTGLANCE_MODELS` → exe 同级 → `../Resources` → `CARGO_MANIFEST_DIR`（4 顺位）；dll 走 `SHOTGLANCE_ORT_DLL` → exe 同级 → exe/models → ../Resources → `CARGO_MANIFEST_DIR/vendor`（5 顺位）；离线模型走 `%APPDATA%\ShotGlance\…`；配置走 `app_config_dir()`；tokens.tsv 走 `BaseDirectory::Resource`。
- **唯一残留**：两处 `env!("CARGO_MANIFEST_DIR")` dev fallback 会被烧进二进制，但正常安装布局下走不到。
- `restore-env-bundle.ps1:210-233` 路径不符时是 **Warn + 跳过 target**，工具链/crate 缓存/node_modules 照常恢复 → 路径不同只多花 30 分钟重编，功能零影响。
- 即：真正的约束是"想复用 target 缓存就得同路径"，缓存是**优化项**不是**依赖项**。
- 待办（未经用户确认）：两处 fallback 加 `#[cfg(debug_assertions)]`；release 加 `--remap-path-prefix`（未实测）；`CARGO_TARGET_DIR` 解耦；`mklink /J` 逻辑路径锁死。
