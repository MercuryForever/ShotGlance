## 编译后环境可删性（已答）
- 三层区分：编译产物（自包含）/ 构建环境（可删）/ 系统运行时（WebView2，不可删）。
- 关键动作：release 构建加 `-C target-feature=+crt-static`，否则 exe 仍依赖 vcruntime140.dll。
- 删 target/ 会连 bundle 产物一起删 → 必须先拷出 dist/ 再 cargo clean。
- 迭代期保留 Rust + target；仅 Python venv 与 node_modules 可立即回收。

## 产物自包含性（已答）
- Windows：真自包含，前提是 `+crt-static`（否则依赖 VCRUNTIME140.dll）+ 处理 WebView2 分发。
- macOS：.app 自包含，WKWebView 系统自带，但需签名+公证否则 Gatekeeper 拦截。

## 窗口生命周期改造完成：80MB 内存红线达成
- 方案：`tauri.conf.json` 的 `app.windows` 置空 → 启动零窗口纯托盘；`Ctrl+Shift+S`/托盘左键按需 `WebviewWindowBuilder` 建窗；Esc/关闭/watchdog 一律 **destroy 而非 hide**（hide 不释放 WebView2 子进程，内存一分不省）
- 三个关键 API 细节（一次编译通过）：
  - `RunEvent::ExitRequested { code, api, .. }` 里必须判断 `code.is_none()` 才 `api.prevent_exit()`；`Some(_)` 是 `app.exit()` 主动退出，放行否则托盘退出失效
  - `.build(ctx)?.run(|app, event|)` 才能拿到 RunEvent，原来的 `Builder::run(ctx)` 拿不到
  - watchdog 用 `std::thread` + sleep 而非 tokio，省一个依赖；AppHandle 是 Send+Sync 可跨线程
- **实测（scripts/measure-memory.ps1，两次一致）**：常驻 11.1MB / 0 个 WebView2 → 开窗 295.6MB / 6 个 → 回收后 23.3MB / 0 个；冷启动到首窗 87–112ms；failures: 0
- 教训：WebView2 子进程数不稳定（5–6 个，205–273MB 波动），测内存必须按 PID 差集归因，不能只看总数
- 可测性开关（已固化，不改变默认行为）：`SHOTGLANCE_OPEN_PANEL=1` 启动即建窗；`SHOTGLANCE_IDLE_SECS=n` 覆盖空闲阈值（默认 120s）
- 沙箱另两个限制：`Start-Process powershell.exe` 被安全策略拦（只能在 PS 工具里直接 `& script`）；PS 工具不回显 stdout → 脚本需自带 `-LogPath` 自行落盘

## 截屏采集接入完成（xcap + WGC）
- 选型：`xcap 0.9.9` + `wgc` feature（Windows.Graphics.Capture），三平台同一套 API；代价是 windows crate，包体 2.87 → 2.97 MiB
- 实测（2560×1440 单屏）：冷启动首次 351ms，预热后稳定 **130–132ms**（预算 300ms，2.3 倍余量）
- **瓶颈不是采集而是编码与首次初始化**：采集稳态仅 39–53ms；PNG 编码 126–143ms vs JPEG q85 72–86ms（体积 1.5MB → 433KB）
- 决策：预览用 JPEG q85；OCR 走内存原始 RGBA 不经过编码，所以有损不影响识别精度
- 预热方案：建窗时后台 `warm_up_once()` 跑一次丢弃，把 273ms 初始化藏进窗口出现的几百毫秒里
- **xcap 用 LazyLock 全局单例缓存 ID3D11Device/IDXGIDevice/GraphicsCaptureItem，无 clear API** → 采集过一次后常驻内存 23MB → 65MB 且不可释放，但只初始化一次、不累积（非泄漏）
- **枚举显示器（Monitor::all）也会初始化这套设备** → 前端改为首次截图成功后才填充显示器下拉，避免"只打开面板"就付 42MB
- 双模式实测均达标：预热 on → 回收后 64.8MB / 首次 130ms；`SHOTGLANCE_WARMUP=0` → 回收后 23.7MB / 首次 351ms
- **WebView2 子进程销毁后需 4–8 秒才退出**（10s 时 6 个 → 14s 时 2 个 → 18s 归零），测量脚本必须轮询等待，固定 sleep 会误报失败
- 可测性：`SHOTGLANCE_SELF_TEST=1` 无界面采集并写 `%TEMP%\shotglance-selftest.txt`（冷/热多轮 + PNG/JPEG 编码对比）

## PowerShell 脚本编码坑（重要，会静默炸）
- **PS 5.1 按 ANSI(GBK) 读无 BOM 的 UTF-8 文件，.ps1 里写中文注释会破坏 param 块解析**，报错为"',' 后面缺少表达式"，且参数会被静默丢弃（params 只解析出前 3 个）
- 规避：项目内所有 .ps1 保持**纯 ASCII**；已给 measure-memory.ps1 加注释警示，可用 Python 检查 `any(b > 127)`
- 排查手法：`[System.Management.Automation.Language.Parser]::ParseFile()` + 把 `$ast.ParamBlock.Parameters` 打印出来，能直接看出哪个参数没被识别
- **更新（OCR 阶段验证）**：中文 .ps1 只要存成 **UTF-8 带 BOM** 就能被 PS 5.1 正确解析（make-ocr-sample.ps1 已实测），"必须纯 ASCII"可放宽为"要么 ASCII，要么 BOM"

## OCR 接入完成（PP-OCRv4 + ONNX Runtime，load-dynamic）
- 模型来源：hf-mirror `SWHL/RapidOCR` PP-OCRv4 det 4.7MB / rec 10.4MB；字典经 ghproxy 取 PaddleOCR `ppocr_keys_v1.txt`（6623 行，UTF-8 无 BOM）
- **类别数 6625 = 1 blank + 6623 字典 + 1 空格**；空格必须挂在最末类，否则英文词全粘一起
- ort 2.0.0-rc.15 的 API 与常见教程差很多：`Session::builder(&Environment)`、`ort::init_from(path)`、`run(&mut self)`、`try_extract_tensor::<f32>() -> (&Shape, &[f32])`、`Tensor::from_array(([1,3,h,w], Vec<f32>))`、`outputs[0]`（Index 实现）
- **借用坑**：`SessionOutputs` 借着 `&mut self.det`，必须先出作用域再借 self 跑识别（用 block 收尾）
- **cdn.pyke.io 实测只有 ~2 KB/s**（32MB 要几小时，ort-sys build script 静默挂死、out 目录空、无 build-script 进程名可见）→ 改从 PyPI 清华镜像取 `onnxruntime-1.31.1` wheel（14888304B，sha256 0558f29d…c2348b），解出 `onnxruntime.dll` 19.3MB
- wheel 里没有 `onnxruntime.lib` → 链接期本来就绑不了，正好用 `load-dynamic`（同时获得"dll 位置自己控制"的好处）
- 自己实现的部分：det 前处理（长边 960、补 32、ImageNet 归一化）+ DB 后处理（二值化 0.3 → 8 邻域连通域 → 均值 0.6 → area×1.5/perimeter 外扩 → 阅读顺序）、rec 前处理（高 48、纵横比定宽）+ CTC 贪心解码；阈值 0.3/0.6/1.5/行 conf 0.5（Paddle drop_score）
- **实测**：测试图 1000×560 → det 80 + rec 161 = 242ms，8/8 行，conf 0.97–1.00；全屏 2560×1440 密集桌面 → det 112 + rec 699 = 811ms，83 行；错字 `阈→阔`、`」→]`
- 瓶颈是 rec ≈ **8.4ms/行**（逐行推理避免 padding 浪费），全屏 80+ 行才成为主项；下一轮可做小批
- **内存**：引擎加载 152.7MB → 面板销毁 `ocr::unload()` 后 32.9MB；线程 2 vs 4 内存几乎一样（151.4 vs 152.7）但时延 +29% → 默认 min(核数,4)
- **Tauri 2 生产构建必须带 `--features tauri/custom-protocol`**：只用 `cargo build --release` 得到的 exe 还是 dev 模式，会去连 localhost:1420 并弹"无法访问此页面"
- NSIS 打包：`bundle.resources` 用对象形式把 `models/*` 放到 `models/`、`onnxruntime.dll` 放到 exe 同级 → 安装包 21.19 MiB
- 新增可测性开关：`SHOTGLANCE_OCR_SELFTEST` / `SHOTGLANCE_OCR_IMG` / `HOLD_SECS` / `UNLOAD_TEST` / `ORT_THREADS` / `ORT_DLL` / `MODELS` / `TOPMOST` / `AUTO_OCR` / `DUMP_IMG`
- 坑：Windows 下给 Rust 传 `/tmp/x.jpg` 会落到 `C:\tmp`（目录不存在则 fs::write 静默失败），必须 `cygpath -w` 转 Windows 路径
