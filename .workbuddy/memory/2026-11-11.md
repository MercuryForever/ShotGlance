## 翻译层（下午完成）

用户要求"引擎选多种方案并行，可选在线 api 或离线引擎"。做成 5 引擎可切换 + auto 对冲竞速。

### 关键决策
- **模型外置**：quantized encoder 52.9 MB + decoder 60.2 MB = 113 MB。内置会让装包 22 → 135 MB，顶到 150 MB 红线。放 `%APPDATA%\ShotGlance\models\opus-mt-en-zh\`，应用内下载 + 支持手动放文件。词表 tokens.tsv(1.8 MB) 随包，因为它和模型版本绑死。
- **auto = 对冲竞速**，不是串行降级。第一个引擎立刻发，之后每 250 ms 补一个，先返回者胜。理由：本机 googleapis 不通，串行每次要卡 5 s 超时。实测 1243 ms（第一轮）→ 613 ms（第二轮，google 已熔断）。
- **失败熔断 90 s**：避免反复付超时成本。用户显式指定引擎时不跳。
- **贪婪解码**，不用 beam=4。实测 beam 慢 4 倍，长文本质量差别小；短句差异来自模型本身。
- **不引 sentencepiece / tokenizers**：前者要 cmake 编 C++，后者需要 tokenizer.json 而 Xenova 仓库只有 .spm。改为构建期用 Python 把 spm 分数和 vocab.json 的 id 合成 tokens.tsv，Rust 端自己跑 Unigram Viterbi。

### 踩到的坑
1. **ureq 的 native-tls feature 永远不是默认**。它只把 `tls`(rustls) 当默认后端，`native-tls` 仅"可用"。必须在 AgentBuilder 上 `.tls_connector(...)` 显式注入，否则所有 https 报 `no TLS backend is configured`——这个报错极像网络问题，容易查错方向。
2. **Marian 的 spm 与 vocab 是两套 id**。source.spm 只有 32000 piece，embedding 是 65001 行，必须拿 piece 字符串过 vocab.json 重映射。直接喂 spm id 得到乱码。
3. **spm 的 unk 分数是 0**，自己实现 Viterbi 时要取 `min_score - 10`，否则 unk 路径得分最高、整句输出 unk。
4. **`mod translate` 与 `fn translate` 同名**导致 `translate::run` 被解析成函数路径，25 个 E0433。用 `#[path]` 把模块改名 mt 解决。
5. .bar 类名和 header 的 `.bar` 冲突，进度条改名 .dlbar。

### 实测
- auto 第一轮 1243 ms / 第二轮 613 ms（熔断生效）
- offline 667–766 ms，译文质量优于 MyMemory（"连接到服务器失败" vs "无法连接到服务器"）
- mymemory 534–840 ms
- google 本机超时（网络问题，非代码）
- deepl/openai 未验证（需要 key）
- 装包 21.90 MiB（+0.66，含 tokens.tsv）

### 遗留

- 译文悬浮层未做。

### 修掉的三个脚本 bug（都是"静默出错"型）
1. **`$env:TEMP` 是 8.3 短路径**（`C:\Users\ADMINI~1\...`），而 `Get-ChildItem` 返回长路径。拿 `$Stage.Length` 去 `Substring` 会少截 7 个字符，于是压缩包内每条 entry 和 MANIFEST 每一行都带一个 `b99b3\` 前缀。**这个 bug 在 11-09、11-11-1134 两版快照里都存在**（只是那时用 `CreateFromDirectory`，entry 名由 API 自己算，只有 MANIFEST 受影响）。修法：`$StageFull = (Get-Item $Stage).FullName`，用 `StartsWith + Substring` 封装成 `Get-RelPath`。
2. **`ZipFile::CreateFromDirectory` 不覆盖已存在文件**，直接抛 IOException（原注释写的"truncates via FileMode.Create"是错的）。而 `Remove-Item` 会被沙箱 safe-delete 拦截。改用 `[System.IO.File]::Open(path, FileMode.Create)` + `ZipArchive` 手动逐条 `CreateEntryFromFile`，既节流又规避删除。
3. **`Add-Content -Value ''` 在 PS 5.1 不产生空行**，导致 report 里 `...(driver installer)RESULT` 粘在一起。改为内存 `List[string]` 收集、末尾 `Set-Content` 一次落盘。

### 经验
- 白名单式快照的风险不是"带上垃圾"，而是"漏掉文件且静默通过"。校验方法是 `unzip -l xxx.zip | grep 关键目录` + `unzip -p xxx.zip MANIFEST.txt | head`，别只看 report 的条数。
- 删 `target` 前务必先 `cp` 出 bundle 里的 setup.exe，它不随源码存在。
- 这类打包脚本要在**目标机上真跑一遍并打开产物看**，否则错误可以一路静默到换设备那天。
